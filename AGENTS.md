# AGENTS.md — правила проекта `aaa`

Область действия: весь репозиторий `D:\scripts\rust\aaa`.
Эти правила дополняют системные инструкции и указания пользователя. При конфликте побеждает прямое указание пользователя в чате.

## Контекст проекта

- Rust, edition 2024, бинарный крейт `aaa`, единственный исходник — `src/main.rs`.
- Инструменты: `cargo 1.99.1`, `clippy 0.1.99`, `rustfmt 1.10.0`.
- Зависимостей пока нет; `Cargo.lock` в репозитории.
- Репозиторий инициализирован, но коммитов ещё нет.

## 1. Plan First — сначала план, потом «ок»

**Триггер:** создание, изменение или удаление любого файла; изменение конфигурации и зависимостей; любая `git`-команда, меняющая состояние; любой запуск, который переписывает файлы.

1. Сначала вывести пошаговый план и **дождаться явного «ок»** от пользователя.
2. План обязан содержать: что именно меняется (файл, суть, при необходимости строка), зачем, как будет проверено, что может пойти не так и как откатить.
3. «Ок» — это явное согласие в чате («ок», «да», «делай»). Молчание, встречный вопрос или уточнение согласием не являются.
4. Если после «ок» план поменялся — нужен новый план и новое «ок».
5. Без плана разрешены только неизменяющие действия: чтение, поиск, `cargo metadata`, `git status` / `git log` / `git diff`, `cargo check` и `cargo clippy` (они пишут только в `target/`).
6. Режим plan mode, если он включён в сессии, действует поверх этого правила; выход из него — только через `exit_plan_mode` с подтверждением пользователя.

## 2. Post-Edit Check — проверка после каждой правки

**Триггер:** любая правка файла `*.rs` (включая новый) или `Cargo.toml`; добавление/обновление зависимости, изменение `Cargo.lock`.

1. Сразу после правки, **до перехода к следующему шагу**, выполнить:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify.ps1
   ```

   Скрипт делает ровно то, что требуется: `cargo fmt --check` → `cargo check --all-targets` → `cargo clippy --all-targets -- -D warnings`.

   На этой машине установлен только Windows PowerShell 5.1 (`powershell.exe`), `pwsh` отсутствует — использовать именно `powershell`.

2. Показать результат: «PASS» по каждому шагу либо ошибки с `файл:строка` и текстом.
3. Ошибки компиляции и clippy-предупреждения **исправить до продолжения работы**. Если исправление меняет поведение или публичный API — это уже новый план (правило 1).
4. Не оставлять проект в некомпилирующемся состоянии к концу хода. Если починить не удаётся — сказать прямо, приложить вывод и предложить откат.
5. `-D warnings` не обходить: не добавлять `#[allow(...)]`, `#[expect(...)]` или `#![allow(...)]` без причины и без разрешения; не отключать линты в `Cargo.toml`.

## 3. Safety — что запрещено

### Неприкосновенная папка

`D:\scripts\rust\aaa-acl-recovery` — **не читать, не изменять, не удалять, не перемещать**, не «чистить заодно», не включать в архивы, бэкапы или коммиты. Там служебные резервные копии прав Windows. Она лежит вне рабочей папки; даже если доступ формально есть — не трогать.

### Разрушительные команды

Без **отдельного явного разрешения** пользователя запрещены:

- `git reset --hard`, `git reset --merge`, `git clean -fd` / `-x` / `-fdx`;
- `git push --force`, `git push --force-with-lease`;
- `git checkout -- .`, `git restore .`, `git restore --staged .` по всему дереву;
- `git branch -D`, `git stash drop`, `git stash clear`, `git rebase` на уже опубликованной ветке;
- любые операции, удаляющие или перезаписывающие `.git`;
- `rm -rf` / `Remove-Item -Recurse -Force` по путям вне `target/`.

Разрешено без отдельного разрешения: правки в `src/` и `scripts/`, `cargo build` / `check` / `clippy` / `fmt` / `run` / `test`, локальные `git status` / `diff` / `log` / `add` / `commit` (по плану), правки `.gitignore` и `AGENTS.md`.

Перед любым деструктивным действием — показать точную команду и полный путь, получить «ок». При сомнении — не выполнять, а спросить.

### Прочее

- Не выводить в чат содержимое `.credentials.yaml`, `.env`, токены, ключи.
- Не добавлять зависимости, не менять edition, имя пакета или профили сборки без плана.
- Не коммитить `target/` (он в `.gitignore`).
